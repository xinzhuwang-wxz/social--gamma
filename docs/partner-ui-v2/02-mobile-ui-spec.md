# 行动森林：移动端 UI 与功能 Spec

> 版本：V0.1  
> 日期：2026-08-12  
> 设计基线：当前 Demo 的 A「沉浸花园」方案。  
> 产品范围：移动端、校园用户、1 对 1 搭子场景。  
> 文档目的：规定导航、页面、组件、状态、交互反馈与业务规则，供产品、设计和开发共同使用。

## 1. 信息架构

### 1.1 底部导航

应用使用四个一级页面加一个全局发布操作：

```text
[种子信箱] [行动] [＋发布] [花园] [我的]
```

| 入口 | 类型 | 主要职责 | 默认状态 |
|---|---|---|---|
| 种子信箱 | 一级页面 | 查看别人投递来的种子和自己的参与意向 | 显示未读数量 |
| 行动 | 一级页面 | 管理已经正式成局的事件 | 显示未读消息数量 |
| ＋发布 | 全局操作 | 唤起个人 Agent，生成并发布种子 | 始终居中突出 |
| 花园 | 一级页面、默认首页 | 查看进行中植物、已完成经历和再次行动入口 | 启动后默认进入 |
| 我的 | 一级页面 | 管理个人资料、Agent 信息权限、隐私与安全 | 无特殊状态 |

### 1.2 导航规则

- 点击一级导航时返回该页面的根状态，不保留上一次打开的详情页。
- `＋发布` 不作为可选中的导航标签，而是打开发布流程。
- 页面存在未保存输入时，离开页面需要提示是否放弃。
- 底部导航在聊天输入、图片预览等需要沉浸操作时可以隐藏；首版也可保持显示，但不得遮挡输入框。
- 默认首页为“花园”。

### 1.3 页面地图

```text
花园
├─ 进行中植物 → 行动房间
├─ 成熟植物 → 共同回忆详情
└─ Agent 状态／推荐入口

种子信箱
├─ 新种子 → 种子详情 → 表达参与意向
└─ 等待回应 → 意向状态详情

发布
├─ Agent 对话
├─ 种子确认
└─ 发布结果／候选人管理

行动
├─ 行动列表
└─ 行动房间
   ├─ 对方信息卡
   ├─ A to A 对话
   ├─ 真人聊天
   ├─ AI 节点辅助
   ├─ 行动约定
   └─ 完成确认与回忆

我的
├─ 基本资料
├─ 兴趣与行动偏好
├─ Agent 对外信息权限
├─ 隐私与共同回忆
└─ 不再匹配的人
```

## 2. 全局视觉规范

### 2.1 设计方向

正式视觉采用“自然、温暖、可信赖”的沉浸花园方向：

- 花园世界观负责情绪表达和进度感知。
- 卡片、文字和按钮负责功能清晰度。
- 重要操作不能只依赖植物图形或隐喻，必须配有明确文字。
- AI 的拟人化语气用于降低压力，时间、地点、隐私等重要信息优先准确直接。

### 2.2 色彩

建议基准色值：

| Token | 色值 | 用途 |
|---|---|---|
| `color-bg` | `#F4F6EF` | 应用背景 |
| `color-surface` | `#FFFEFA` | 卡片、弹层、输入框 |
| `color-primary` | `#3F7851` | 主按钮、选中状态、关键链接 |
| `color-primary-soft` | `#E8F0E1` | 标签、次级按钮、选中背景 |
| `color-accent` | `#83A86F` | 植物进度、边框强调 |
| `color-agent` | `#FFF4D9` | Agent 对话和 AI 卡片背景 |
| `color-text` | `#193126` | 主文本 |
| `color-text-secondary` | `#718078` | 辅助文本 |
| `color-danger` | `#9C534D` | 删除、结束、不再匹配等风险操作 |
| `color-danger-soft` | `#F8E8E5` | 风险操作浅色背景 |

使用规则：

- 主色只用于主操作、当前导航和确认状态。
- AI 内容统一使用暖黄色系背景，避免与真人消息混淆。
- 红色只用于不可逆或关系终止类操作，不用于普通未完成状态。
- 植物状态不能只靠颜色区分，必须同时显示图形和文字。

### 2.3 字体与层级

字体栈：`PingFang SC`、`Microsoft YaHei`、系统无衬线字体。

| 层级 | 字号 | 字重 | 典型用途 |
|---|---:|---:|---|
| 页面标题 | 24 px | 700–800 | 花园、种子信箱、行动 |
| 详情标题 | 20 px | 700 | 种子标题、事件标题 |
| 区块标题 | 16 px | 700 | 正在生长、我的森林 |
| 卡片标题 | 14–15 px | 700 | 行动名称、候选人名称 |
| 正文 | 13–14 px | 400–500 | 对话、说明、信息内容 |
| 辅助文字 | 11–12 px | 400–600 | 时间、状态、解释 |
| 标签 | 10–11 px | 700–800 | 状态、认证、类别 |

- 正文行高建议为 1.5–1.6。
- 单行卡片标题最多两行，超出截断。
- 重要时间、地点不得用过浅的辅助色。

### 2.4 间距、圆角与点击区域

- 页面水平边距：18 px。
- 区块间距：20–24 px。
- 卡片内边距：16–18 px。
- 卡片间距：10–12 px。
- 主卡片圆角：20–24 px。
- 小卡片、输入框圆角：14–16 px。
- 按钮最小高度：46 px。
- 图标按钮最小点击区域：44 × 44 px。
- 底部导航高度：72–76 px，并适配系统安全区。

### 2.5 按钮层级

| 类型 | 样式 | 使用场景 |
|---|---|---|
| Primary | 绿色实底、白字 | 发布种子、愿意参与、选择同行、确认约定、完成 |
| Secondary | 浅绿底、深绿字 | 修改、查看资料、继续讨论、再约一次 |
| Ghost | 无底色、次要文字色 | 返回、暂不感兴趣、取消 |
| Danger | 浅红底、深红字 | 结束事件、不再匹配、删除自己的回忆内容 |

- 一个页面的可视区域原则上只出现一个主按钮。
- 危险操作不能与主操作使用相同颜色。
- 提交后立即进入加载状态，防止重复点击。

### 2.6 卡片通用规范

卡片由以下部分按需组合：

1. 状态标签。
2. 标题。
3. 关键事实。
4. AI 解释或来源。
5. 主次操作。

AI 推荐理由必须可读、可解释，例如“你们周六都有时间，并且都希望轻松路线”，不展示缺乏解释的百分制匹配分。

### 2.7 状态反馈

- 成功：短 Toast + 页面状态立即更新。
- 失败：保留用户输入，展示原因和重试按钮。
- 等待：使用局部骨架屏或按钮加载，不全屏阻塞。
- 空状态：说明为什么为空，以及用户可以做什么。
- 未读：使用数量徽标；单纯红点仅用于低优先级提示。

## 3. 全局业务组件

### 3.1 植物状态组件 `PlantStage`

#### 输入

- 事件状态。
- 事件标题。
- 当前状态说明。
- 是否存在待处理事项。

#### 映射

| 事件状态 | 图形 | 显示文案 |
|---|---|---|
| 匹配中 | 种子 | 正在寻找同行者 |
| 已成局／破冰中 | 嫩芽 | 刚刚成为搭子 |
| 讨论中 | 绿叶幼苗 | 正在商量行动 |
| 已约好 | 花苞 | 已经约好，等待行动 |
| 已完成 | 开花 | 这次行动完成了 |
| 已沉淀 | 成熟植物 | 已成为共同回忆 |

#### 规则

- 植物只在事件跨过真实阶段时变化。
- 不用聊天条数、登录天数或点击次数驱动成长。
- 状态切换可播放 600–1000 ms 的轻量过渡动画。
- 动画不得阻断用户继续操作。

### 3.2 Agent 消息组件 `AgentMessage`

- 暖黄色背景。
- 左上角显示 Agent 头像和身份：个人 Agent 或事件 AI。
- 如消息包含 AI 总结或推断，显示“由 AI 根据本次事件信息整理”。
- 重要建议必须允许忽略、修改或继续聊天。

### 3.3 行动种子卡 `SeedCard`

必须展示：

- 行动名称。
- 大致时间和地点。
- 发起人的基本公开身份。
- 两条以内的行动标签。
- Agent 匹配理由。
- 当前状态。

列表卡不展示完整个人资料，也不展示候选数量。

### 3.4 用户摘要卡 `EventProfileCard`

只展示与当前事件有关的信息：

- 头像、昵称、校园认证。
- 相关兴趣或经验。
- 双方共同点。
- 本次行动仍需沟通的事项。

禁止展示：联系方式、敏感地点、未经确认的性格判断、公开负面评价。

### 3.5 行动约定卡 `AgreementCard`

包含：

- 行动名称。
- 时间或时间范围。
- 地点、集合方式或线上入口。
- 双方已明确的重要备注。
- 双方确认状态。
- 修改入口。

AI 只能把聊天中已经出现的共识写入卡片。

## 4. 页面详细 Spec

## 4.1 花园首页

### 页面目标

让用户一眼看见当前正在推进的行动、已经完成的经历，以及发起下一次行动的入口。

### 页面结构

1. 顶部问候与通知入口。
2. 花园 Hero：个人 Agent、当前总体状态、主植物。
3. “正在生长”：进行中事件列表。
4. “我的森林”：已沉淀的共同经历。
5. 底部导航。

### Hero 区

展示：

- 当前进行中事件数量。
- 最近一个最需要关注的事件。
- 个人 Agent 的一句状态提示。
- 对应事件的植物形态。

点击主植物或提示气泡，进入相应行动房间。

### 正在生长

每张事件卡展示：

- 植物状态。
- 事件名称。
- 同行者昵称。
- 当前阶段文案。
- 未读或待处理提示。

排序规则：

1. 有待处理事项。
2. 即将发生的行动。
3. 最近更新。

### 我的森林

- 默认展示最近三项共同回忆。
- 卡片展示植物、事件标题和同行者。
- 点击进入共同回忆详情。
- 点击“全部回忆”进入完整森林视图；首版可以同页展开代替新页面。

### 空状态

没有进行中事件时：

> “花园里还没有正在生长的行动。种下一件最近想做的事吧。”

提供主按钮“发布种子”。

没有共同回忆时：

> “完成一次真实行动后，它会在这里开花。”

### 页面规则

- 未经双方同意的事件不能进入“我的森林”。
- 已结束不沉淀的事件不在首页留下枯萎植物。
- 花园只展示用户有权限查看的信息。

## 4.2 发布需求：Agent 对话页

### 页面目标

通过逐题点选快速形成一颗可匹配的行动种子，只在选项无法覆盖时使用一句短输入。

### 进入方式

- 点击底部中央 `＋`。
- 从花园空状态点击“发布种子”。
- 从共同回忆点击“让它结出新种子”。

### 页面结构

1. 顶栏：返回、标题“种下一件想做的事”。
2. 个人 Agent 身份区。
3. 对话记录。
4. Agent 根据上一题动态生成的单题选项。
5. “其他，我自己说”兜底入口。

### 对话规则

1. Agent 首先询问“最近有什么想和别人一起做的事？”
2. 用户选择一个最接近的行动意愿。
3. Agent 根据上一项答案，只追问一个影响匹配的缺失项。
4. 同一轮最多追问一个问题，避免形成问卷。
5. 信息基本完整后，Agent 生成种子确认卡。

发布页采用“对话式单题选择”：每次只显示 Agent 的一个问题和少量答案，用户点选后进入下一题。题目与选项根据前一步动态生成，不一次展示完整表单。

- 第一题可以用常见活动帮助用户快速开始。
- 后续问题围绕时间、地点和必要偏好，每次只问一项。
- 每题最多提供四个常用答案。
- 始终保留“其他，我自己说”，用于无法被选项覆盖的需求。
- “其他”只需要一句短输入，不要求用户填写长段描述。
- 用户随时可以返回修改上一项。

### 最小字段

| 字段 | 必填 | 示例 |
|---|---|---|
| 行动名称／类型 | 是 | 周六一起轻松爬山 |
| 大致时间 | 是 | 本周六，具体时间可商量 |
| 大致地点 | 是 | 学校附近 |
| 搭子必要要求 | 否 | 接受新手，希望沿途拍照 |

### 异常状态

- 用户只输入“随便找个人玩”：Agent 追问具体想做什么。
- 时间或地点完全不可判断：追问其中影响更大的一个。
- 用户离开：若存在输入，提示保存草稿或放弃。
- AI 生成失败：保留原始输入并允许重新整理。

## 4.3 种子确认页

### 页面目标

让用户在发布前确认 Agent 理解是否准确。

### 页面内容

- 种子状态“待发布”。
- 行动标题。
- 时间。
- 地点。
- 搭子要求。
- 信息公开范围提示。
- “修改”与“让 Agent 出发”。

### 操作

#### 修改

- 返回 Agent 对话。
- 定位到用户要修改的字段。
- 修改后重新生成预览。

#### 让 Agent 出发

- 用户点击后显示局部加载动画。
- 创建事件草稿并进入“匹配中”。
- 跳转发布结果页，而不是直接出现候选人；Demo 中的候选人即时返回只是模拟。

### 发布结果

展示：

> “种子已经出发，小叶会把它送到合适的信箱。”

提供：

- 查看匹配进度。
- 返回花园。
- 取消本次种子。

## 4.4 种子信箱页

### 页面目标

集中展示个人 Agent 为用户带回的行动机会。

### 页面分组

1. **收到的种子**：尚未回应。
2. **等待回应**：用户已经表达参与意向，等待发起人选择。

已拒绝、已被其他人选中或过期的种子从主列表移除，可在历史记录中查看，首版可不提供历史入口。

### 收到的种子列表卡

展示：

- 行动名称。
- 明确标注的时间和地点；不得只用缺少上下文的兴趣标签代替关键行动条件。
- 发起人昵称与认证状态。
- Agent 推荐理由。
- 新消息状态。

列表卡的信息优先级为“行动名称 → 时间／地点 → 发起人 → 匹配理由”。“胶片感”“轻松散步”等氛围或兴趣词不作为首屏关键信息；如确有价值，应放入详情页并说明它属于偏好、要求还是活动形式。

点击进入种子详情。

### 等待回应列表卡

展示：

- 事件名称。
- “已表达参与意向”。
- 发起人是否已处理。
- 用户附带的留言。

首版不展示排队人数和预计等待时间。

### 空状态

收到的种子为空：

> “暂时没有新的种子，小叶会继续帮你留意。”

等待回应为空：

> “你还没有回应任何种子。”

## 4.5 种子详情页

### 页面目标

帮助候选人同时判断“这件事是否适合我”和“我是否愿意与这个人同行”。

### 页面结构

1. 行动视觉和标题。
2. 完整行动信息。
3. 发起人有限公开资料。
4. Agent 匹配理由。
5. 可选留言输入框。
6. “暂不感兴趣”和“愿意参与”。

### 可展示信息

- 时间、地点、行动要求及可协商项。
- 发起人头像、昵称、校园认证。
- 与本次事件有关的兴趣和经验。
- 公开的相关共同经历数量。

### 不可展示信息

- 手机号、微信等联系方式。
- 精确宿舍、常用活动轨迹。
- 与事件无关的详细个人资料。
- AI 推断出的敏感性格判断。

### 愿意参与

点击后：

1. 若填写了留言，将留言与参与意向一同提交。
2. 页面进入“等待发起人选择”。
3. 种子移动到信箱的“等待回应”。
4. 不开放行动房间，也不开放联系方式。

### 暂不感兴趣

- 种子从新列表移除。
- 不通知发起人是谁拒绝。
- 此次拒绝不构成负面评价。

## 4.6 发起人：匹配进度与候选人选择页

### 页面目标

让发起人在多个明确表达意向的候选人中选择一名同行者。

### 状态一：等待候选人

展示：

- 种子信息。
- Agent 正在投递的状态。
- 已收到参与意向数量。
- 返回花园和取消种子操作。

### 状态二：候选人列表

每张候选人卡展示：

- 头像、昵称、校园认证。
- 候选人的一句话留言。
- 与本次事件相关的经验与偏好。
- AI 匹配理由。
- 需要进一步协商的事项。
- “查看资料”和“选择同行”。

### 排序原则

1. 必要条件是否满足。
2. 时间与地点是否兼容。
3. 与事件有关的经验或偏好。
4. 历史上双方是否有成功共同行动。

不展示抽象匹配分数，也不将候选人标为“第一名”。

### 选择同行

点击后展示确认弹层：

> “确认邀请小林成为这次行动的搭子吗？”

确认后：

- 创建 1 对 1 事件行动房间。
- 种子停止继续投递和接收意向。
- 被选择者收到成局通知。
- 其他候选人收到礼貌结束通知。
- 双方的种子从信箱移除，事件出现在“行动”。

### 其他候选人通知

统一文案：

> “这颗种子已经找到了同行者。感谢你的回应，小叶会继续帮你寻找相似的行动。”

不展示发起人选择了谁，也不表达候选人“不合适”。

## 4.7 行动列表页

### 页面目标

展示已经正式成局的事件及其当前状态。

### 分组

- 进行中：破冰中、讨论中、已约好、待完成确认。
- 已结束：已沉淀、结束不沉淀；首版可仅保留最近记录。

### 事件列表项

展示：

- 植物状态。
- 事件名称。
- 同行者。
- 最后一条真人消息或状态提示。
- 未读数量或待确认提示。
- 最近更新时间。

### 排序规则

1. 需要当前用户确认的事件。
2. 有未读消息的事件。
3. 即将发生的事件。
4. 最近更新的事件。

点击进入行动房间。

## 4.8 行动房间：首次进入与破冰

### 页面目标

让两个已经成局的用户自然接过 Agent 的交流，而不是从空白聊天框开始。

### 页面结构

1. 顶栏：事件名称、同行者、更多设置。
2. 植物状态条。
3. 对方信息摘要卡。
4. A to A 对话记录。
5. Agent 交接完成提示。
6. 真人聊天区。
7. 输入框与“请小苗帮忙”入口。

### 植物状态条

展示：

- 当前植物形态。
- 当前阶段，如“刚刚成为搭子”或“正在商量行动”。
- 若已形成约定，显示约定的时间和地点摘要。

点击状态条可查看完整事件状态；首版也可不提供展开页。

### 对方信息摘要卡

默认展示两到三项与事件有关的信息，支持展开：

- 相关经验。
- 兴趣与偏好。
- 双方共同点。

卡片来源需显示为“由双方 Agent 根据公开信息整理”。

### A to A 对话

- 作为聊天历史顶部的一段特殊内容展示。
- 默认展示三轮以内的可读对话。
- 支持折叠。
- 明确标注“以下是两位 Agent 在匹配过程中的交流”。
- 不展示系统提示、模型推理或未经允许的信息。

### Agent 交接完成提示

A to A 内容下方显示一条非对话气泡式系统提示：

> “两位 Agent 已完成交接。接下来由你们决定具体怎么安排；聊到卡住时，可以请小苗帮忙。”

这里不再由事件 AI 主动替双方开场，也不提供预设快捷回复。A to A 对话已经完成“为什么匹配”的解释，真人对话从此处正式开始。

### 破冰结束条件

- 双方都至少发送一条真人消息，或双方已经围绕事件展开有效交流。
- 破冰结束后，对方信息卡和 A to A 对话默认折叠。
- 植物从嫩芽进入长叶状态。

## 4.9 行动房间：真人聊天与 AI 推进

### 页面目标

保持普通聊天的自然感，同时让用户在具体决策节点上随时获得帮助。

### 输入区

包括：

- “请小苗帮忙”按钮。
- 文本输入。
- 发送按钮。
- 图片或位置等附件入口可后置。

### 点击“请小苗帮忙”

事件 AI读取与本次决策有关的最近对话，提供一种轻量帮助：

- 总结当前共识。
- 指出仍未确定的问题。
- 整理少量选择。
- 提出一个可接受或继续讨论的建议。

示例：

> “你们目前都倾向磨山。要不要暂定周六下午 3 点，在学校北门集合？”

操作：

- “就这样约”。
- “再聊聊”。

复杂场景可以显示两到三个选项，但不得生成完整项目计划。

### AI 规则

- 首版以用户主动点击为主要触发。
- 一次只处理一个卡点。
- AI 建议必须基于对话中已有信息。
- 用户选择“再聊聊”后，AI 退出，不继续追问。
- 用户选择建议后，信息只作为待整理共识，不立即成为不可修改承诺。

### 角色与介入规则

- 两位个人 Agent 只在匹配阶段交流；正式成局后完成交接，不继续替用户聊天。
- 真人负责开口、表达偏好、协商以及作出所有实质决定。
- 小苗是事件内的行动助手，默认不发言，只在用户主动点击“请小苗帮忙”后介入。
- 小苗只能根据最近的真人对话总结卡点、整理选项或提出一个建议。
- 小苗的建议必须明确标注“具体安排由你们决定”。
- 是否采纳建议、是否形成约定以及约定内容均由双方真人确认。

### 消息类型

| 类型 | 样式 | 是否可撤回／修改 |
|---|---|---|
| 自己消息 | 主绿色、右侧 | 按常规聊天规则 |
| 对方消息 | 白色、左侧 | 仅对方控制 |
| 个人 Agent 历史 | 暖黄、特殊标记 | 不可修改，允许折叠 |
| 事件 AI | 暖黄、居中或左侧 | 可忽略，建议可重新生成 |
| 系统状态 | 浅绿小标签 | 不可编辑 |

## 4.10 行动约定

### 生成方式

- 双方讨论基本明确后，任意一方点击“整理约定”，或接受 AI 的整理建议。
- AI 根据已有对话生成约定草稿。
- 双方分别确认。

Demo 中“就这样约”直接形成约定用于演示；正式版本需要保留双方确认状态。

### 约定卡内容

- 行动名称。
- 时间。
- 地点或集合方式。
- 双方明确提到的必要备注。
- 双方确认头像或状态。
- 修改入口。

### 双方确认

- 第一个用户确认后显示“等待对方确认”。
- 第二个用户确认后，事件进入“已约好”。
- 植物长出花苞。
- 卡片固定在聊天顶部，聊天记录中保留生成时的系统消息。

### 修改规则

- 任意一方可点击修改并提出新版本。
- 新版本需要双方重新确认。
- 在新版本确认前，旧约定保持有效并标记“正在协商修改”。

## 4.11 行动当天状态

### 页面目标

让用户快速找到行动约定，不增加不必要的工具复杂度。

### 行动房间置顶内容

- 行动时间。
- 集合地点或线上入口。
- 必要备注。
- “计划有变化”入口。
- “已完成”入口。

首版不提供持续定位、轨迹或强制到场证明。

### 计划变化

点击后提供：

- 需要修改时间或地点。
- 这次无法继续。
- 返回聊天协商。

修改约定仍需双方确认。

## 4.12 双方完成确认页

### 页面目标

确认真实行动是否发生，并进入回忆与关系选择阶段。

### 页面结构

1. 当前植物与事件标题。
2. 双方确认状态。
3. 当前用户“确认完成”。
4. 等待对方提示。

### 规则

- 双方分别确认，互不代替。
- 第一方确认后，页面显示“等待对方确认”。
- 双方都确认后，植物开花，展开回忆与私密评价表单。
- 一方点击完成后仍可在短时间内撤回；对方确认后不可直接撤回，需要联系支持或双方协商。
- 未完成时可返回行动房间继续讨论，不能强制进入评价。

## 4.13 回忆记录与私密评价页

### 页面目标

让用户留下自愿的共同经历，并私下决定是否还愿意与对方再次行动。

### 页面结构

1. 上传照片，可选。
2. 文字记录，可选。
3. 是否愿意再次组队，必选。
4. 可选体验标签或私密备注。
5. 完成按钮。

### 照片

- 支持从相册选择或拍照。
- 上传前可预览和删除。
- 明确提示只有双方同意生成回忆后才会进入共同回忆。
- 每位用户只能管理自己上传的照片。

### 文字记录

- 输入一句话或短文本。
- 明确标记内容归属。
- 用户只能修改或删除自己写的部分。

### 私密关系选择

选项：

- “愿意再约”。
- “以后不再匹配”。

说明文案：

> “你的选择不会展示给对方。只有双方都愿意，才会生成共同回忆。”

### 提交结果

#### 双方均选择“愿意再约”

- 生成共同回忆。
- 植物进入双方森林。
- 两人进入历史优先匹配关系。
- 展示“再约一次”。

#### 任意一方选择“不再匹配”

- 不生成双方公开可见的共同回忆。
- 对方只看到“本次事件已结束”。
- 系统降低或阻止两人再次匹配。
- 相关选择保持私密。
- 系统仅保留完成、安全和审核所需的后台记录。

### 待对方选择状态

若当前用户已提交、对方尚未提交：

- 显示“等待对方完成回顾”。
- 不提前透露是否会生成共同回忆。
- 用户自己的照片和文字保持私密草稿状态。

## 4.14 共同回忆详情页

### 页面目标

展示双方共同同意保留的真实经历，并提供再次行动入口。

### 页面内容

- 成熟植物或事件封面。
- 行动名称与日期。
- 参与双方。
- 双方各自上传的照片。
- 双方各自的文字记录。
- 从种子到开花的简化成长记录，可选。
- “让它结出新种子”。

### 隐私规则

- 默认仅双方可见；公开范围由双方分别授权。
- 一方撤回自己的照片或文字，只移除该用户的内容。
- 是否允许整棵植物继续公开，需要遵守双方最严格的可见范围。
- 任何用户都不能修改对方内容。

### 再约一次

点击后：

1. 继承原活动类型和原搭子。
2. 打开发布流程的种子确认阶段。
3. 用户修改新的时间、地点或必要条件。
4. 发布为定向邀请，不进入公开候选池。
5. 对方接受后创建新的独立事件。

## 4.15 我的页面

### 页面目标

管理个人身份、Agent 可使用的信息和隐私安全设置。

### 页面区块

#### 基本资料

- 头像与昵称。
- 学校和校园认证。
- 年级或身份，可选择是否公开。

#### 兴趣与行动偏好

- 用户主动填写的兴趣。
- 常参与的活动类型。
- 时间和行动强度等偏好。

#### Agent 对外使用的信息

逐项控制个人 Agent 在 A to A 对话中可以使用的信息：

- 兴趣。
- 活动经验。
- 大致空闲时间。
- 已公开的森林经历。
- 其他用户主动授权信息。

默认不允许使用联系方式、精确位置和敏感个人属性。

#### 隐私与共同回忆

- 默认回忆可见范围。
- 照片使用权限。
- 是否允许出现在对方公开森林。
- AI 总结内容的预览与纠错入口。

#### 不再匹配的人

- 查看已屏蔽或不再匹配的用户。
- 支持解除限制。
- 不显示对方是否也做过相同选择。

## 5. 通知规范

### 5.1 站内通知类型

| 事件 | 通知内容 | 点击去向 |
|---|---|---|
| 收到新种子 | “小叶为你带回了一颗摄影种子” | 种子详情 |
| 候选人回应 | “有人愿意加入你的爬山种子” | 候选人列表 |
| 正式成局 | “你和小林成为了这次行动的搭子” | 行动房间 |
| 未被选择 | “这颗种子已经找到同行者” | 种子信箱 |
| 新真人消息 | 展示事件名与消息摘要 | 行动房间 |
| 待确认约定 | “行动约定正在等你确认” | 约定卡 |
| 待确认完成 | “小林已确认完成这次行动” | 完成确认页 |
| 共同回忆生成 | “你们的植物已经进入森林” | 回忆详情 |
| 再约邀请 | “小林想让这次经历结出新种子” | 定向种子详情 |

### 5.2 通知原则

- 不使用焦虑型倒计时或候选人竞争文案。
- 不在通知中泄露私密评价结果。
- AI 推进建议不默认发送系统推送，避免过度打扰。
- 用户可分别关闭新种子推荐、行动提醒和回忆激活提醒。

## 6. 空状态、异常与边界

### 6.1 匹配暂时无结果

展示：

> “小叶暂时还没找到合适的同行者，会继续帮你留意。”

可操作：修改种子、继续等待、取消。

### 6.2 候选人已经被其他事件占用

不直接暴露对方状态，提示：

> “对方目前无法加入这次行动，小叶会继续寻找。”

### 6.3 一方退出事件

首版提供：

- 发起人重新发布同一颗种子。
- 结束事件。

退出原因不公开展示，不生成枯萎植物或公开负面记录。

### 6.4 AI 理解错误

- 每个 AI 摘要和行动约定都提供“修改”或“纠正”入口。
- 用户纠正后，最新明确表达优先于历史推断。
- 涉及时间、地点等关键内容必须双方确认。

### 6.5 网络失败

- 聊天消息显示发送中、失败和重试状态。
- 发布、确认、评价等操作必须幂等，避免重复创建事件。
- 未提交的文字和照片应保留本地草稿。

## 7. 无障碍与内容规范

### 7.1 无障碍

- 正文与背景对比度不低于 WCAG AA。
- 关键状态同时使用图形、文字和颜色。
- 所有图标按钮提供可读标签。
- 支持系统字体缩放至 130% 时不遮挡主操作。
- 动画遵循系统“减少动态效果”设置。
- 输入和按钮聚焦状态清晰可见。

### 7.2 文案语气

- 温和，但不幼稚。
- 鼓励行动，但不制造负罪感。
- 失败、拒绝和退出使用中性表达。
- AI 不冒充用户，也不暗示自己替用户作出了决定。

推荐：

> “需要我帮你们整理一下目前的选择吗？”

避免：

> “你们怎么还没决定？小苗快要枯萎了。”

## 8. 埋点建议

### 8.1 关键事件

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `seed_create_started` | 打开发布页 | 来源入口 |
| `seed_published` | 确认发布 | 活动类型、字段完整度 |
| `seed_viewed` | 打开种子详情 | 种子 ID、投递来源 |
| `seed_intent_submitted` | 点击愿意参与 | 是否附留言 |
| `candidate_selected` | 发起人确认同行者 | 候选数量、匹配原因类型 |
| `event_room_opened` | 首次进入行动房间 | 是否查看 A to A 对话 |
| `icebreaker_replied` | 发送第一条真人消息 | 手动输入 |
| `ai_progress_requested` | 点击请小苗帮忙 | 当前事件阶段 |
| `agreement_confirmed` | 双方确认约定 | 从成局到约定耗时 |
| `action_completed` | 双方完成确认 | 从约定到完成耗时 |
| `partner_preference_submitted` | 提交是否再约 | 仅记录结果，不用于公开展示 |
| `memory_created` | 双方同意生成回忆 | 是否含照片／文字 |
| `action_restarted` | 从回忆再次发起 | 原事件类型 |

### 8.2 重点漏斗

```text
种子发布
→ 获得参与意向
→ 选择同行者
→ 双方开始真人交流
→ 形成行动约定
→ 双方确认完成
→ 双方愿意再次组队
→ 发起下一次行动
```

## 9. 验收主链路

首版必须可以完整演示以下流程：

1. 用户从花园点击 `＋`。
2. 与个人 Agent 对话并生成种子卡。
3. 确认发布后进入匹配中。
4. 多名候选人收到种子并表达参与意向。
5. 发起人查看候选人并选择一人。
6. 双方进入行动房间，看到对方摘要和 A to A 对话。
7. 系统提示两位 Agent 已完成交接。
8. 两名用户自行开始真人对话。
9. 用户点击“请小苗帮忙”，AI 辅助当前决策节点。
10. AI 整理行动约定，双方分别确认。
11. 行动发生后双方分别确认完成。
12. 双方上传可选照片、文字并私密选择是否再约。
13. 双方都愿意时，共同回忆进入双方森林。
14. 用户从回忆点击“让它结出新种子”，发起下一次行动。

## 10. Demo 与正式实现的差异

当前 Demo 用于验证结构和体验，因此采用即时模拟。正式实现需补齐：

- 发布后异步等待候选人，而非立即出现候选列表。
- A to A 对话由真实匹配过程生成，并经过隐私过滤。
- 候选人和发起人分别由独立账号操作。
- 行动约定需要双方分别确认。
- 完成确认和“是否再约”需要双方分别提交。
- 共同回忆只在后台判定双方均同意后生成。
- 消息、照片、评价和事件状态需要服务端持久化。
