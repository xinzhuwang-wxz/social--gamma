# 关系花合成 v0

## 一句话规则

一朵经历花代表一次真实共同经历；与同一个人种下至少两朵经历花后，用户可以主动让它们“共鸣”，得到一朵不替代原花的关系花，以及一本串联全部源手账的关系手账。

## 为什么高阶

等级只由已经共同完成并允许进入森林的经历数决定，不用“更好看”这种主观指标，也不鼓励刷消息或虚构故事。

| 等级 | 门槛 | 植物形态 | 稳定视觉语言 |
| --- | ---: | --- | --- |
| L1 经历花 | 1 段 | 单层花冠 | 一种真实花卉、一组经历证据纹样 |
| L2 双生共鸣花 | 2 段 | 双层同心花冠 | 一个新轮廓，可辨认继承两个源特征 |
| L3 三章故事花 | 3 段 | 三向分枝花冠 | 三条主枝汇入同一花心 |
| L4 四序花冠 | 4 段 | 四向冠状复瓣 | 第二圈花冠，更宽、更稳定的剪影 |
| L5 五星共生花 | 5 段 | 五瓣星冠 | 关系专属纹样成为稳定花心 |
| L6–L9 同行枝冠 | 6–9 段 | 可数分枝花冠 | 以主枝数编码成长，不无限堆花瓣 |
| L10–L24 共生王冠 | 10–24 段 | 冠形多花簇 | 反复出现的共同元素成为关系徽记 |
| L25–L49 记忆花簇 | 25–49 段 | 层叠记忆花簇 | 高密度但仍有主次，旧纹样成为花脉 |
| L50–L99 关系花树 | 50–99 段 | 小型开花树 | 从花升级为有主干和树冠的标志剪影 |
| L100 百忆神树 | 100 段 | 发光纪念花树 | 专属树冠、层级与光脉共同表达稀有度 |

高阶花可以更精致，但不应只是简单放大。用户应该能通过花冠层数、分枝、花脉与纹样数量读出等级；尺寸只作为很弱的辅助信号。

## 合成与手账规则

1. 只有同一组关系中的、已完成且满足共同回忆隐私门槛的花可以合成。
2. 合成由用户主动发起，AI 不自动替用户建立关系叙事。
3. 源花与源手账永久保留；关系花只是新增一个聚合视图。
4. 关系手账按时间展示每一段源故事，明确标注事实来源，不把模型补写当成现场事实。
5. 新经历发生后，关系花吸收新的颜色、纹样和章节；等级始终等于共同经历数，在 2/3/4/5/6/10/25/50/100 段切换关键形态。

## 花园、森林与关系花园

- **首页展示花园**只有 6 个与底图土坑一一对应的真实花坛位，是用户主动策展的空间。任何新花（包括刚合成的高级花）都不会自动出现；用户点击空土坑进入森林选花，花坛满时需要先换下一朵。空花坛本身不叠加加号、虚线或文案。
- **朋友花园不是第二个页面组件**。小绿走到首页小桥后打开可搜索的联系人列表；选人后仍渲染同一张首页底图与同一组 6 个花坛锚点，只替换其中的关系花。
- **桥是花园驿站**：可切换“我的展示花园”“我和某人的共同花园”，也可拜访联系人的个人花园。前两者是我种过的花的子集；联系人个人花园是对方自己的集合，可能与我有交集，也可能没有。
- **首页场景物体先由小绿交互再打开界面**：门、信箱、桥、花与空花坛均遵守“点击目标 → 小绿走到停靠点并反馈 → 打开二级页面或弹层”。桥面是河面上唯一开放的可行走区域；六个花坛区域也允许自由行走。
- **首页弹层共用同一套视觉语言**：黄色卡通面板、深色描边、米黄内容卡和橄榄绿状态，桥的花园驿站、种子信箱和装扮抽屉不再各用一套皮肤。
- **森林是完整仓库**，等级与联系人是可组合的两个筛选维度，例如 `L1 × 橘子汽水`；不在森林里纵向堆叠联系人花园入口。
- **森林花库**保存全部 L1 经历花和 L2+ 关系花，支持按 L1–L5 等级筛选，并显示每朵花是否已经种在首页。
- **关系花园**以朋友为维度复用首页花园场景。同一个花园骨架在选择不同朋友时种入不同的共同经历花；它是空间视图，不是瀑布流筛选结果。
- 每朵花仍可打开自己的经历手账；关系花可打开聚合手账。因此“花园展示”和“故事阅读”是两层互补视图。

## 真实生成链路

队友导入的 `generate-memory-flower` skill 用于 L1：规范化经历后调用编译器，输出单一真实花卉、`isHybrid=false`、Visual DNA、提示词、候选排序和证据引用。关系花属于独立成熟进化层，不能混入 L1 规则。

`POST /api/bloom-fusions` 当前返回的关系花 `artwork.request` 版本为 `bloom-artwork.v1`。它已经包含：

- 所有源花图片 URL；
- 经历标题、日期、地点与参与者确认的摘要；
- 从各段经历提取的颜色与视觉母题；
- 目标等级及对应植物结构。

当前链路已接入 Doubao 理解模型与 Seedream 图生图：理解模型先把两张源花的形态、两段事实回忆和目标等级编译为关系花视觉计划；Seedream 使用两张源图生成；理解模型再将成图与两张源图并排审查。只有“第一眼可见升级、单株完整、两个源特征可辨、两段回忆纹样可辨、总分不低于 78”同时满足才写回 `artwork.status=ready`，最多自动修正重生两次。

Seedream 5.0 要求输入生成面积至少 3,686,400 像素，因此接口生成 2048×2048，再用 `sharp` 归一化为 skill 契约要求的 1024×1024 PNG。通过验收的图和 manifest 缓存在 `public/world/generated/`；同一谱系重复请求会直接复用，避免重复成本。
